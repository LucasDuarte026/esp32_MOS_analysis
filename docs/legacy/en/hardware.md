# Hardware Architecture

The platform's hardware is designed to control and measure the terminal voltages and currents of a device under test (DUT) with high precision using easily accessible low-cost components. 

```
ESP32 DevKit ─── I²C Bar (400 kHz) ─── MCP4725 @ 0x60 (Gate DAC)
                                    ─── MCP4725 @ 0x61 (Drain DAC ─► LT1013 Buffer)
                                    ─── ADS1115 @ 0x48 (16-bit ADC, 4-channels)

ADS1115 ADC Mapping:
  A0 ──► Raw Shunt Voltage (1 Ω or 100 Ω)      [High currents]
  A1 ──► Drain Terminal Voltage ($V_d$)         [VDS closed-loop feedback]
  A2 ──► Gate Terminal Voltage ($V_g$)          [VGS closed-loop feedback]
  A3 ──► Amplified Shunt Voltage ($\times 31.3$) [Low currents / Subthreshold]

GPIO14 ──► 2N3904 Transistor ──► GND            [Active Bleeder for Drain discharging]
GPIO12 ──► Ground Jumper                        [Hardware Debug Logging Enable]
```

---

## 1. Key Components

### 1.1 Microcontroller: ESP32 Wroom 32D
Provides the processing power and native 2.4 GHz Wi-Fi stack to host the asynchronous web server. By leveraging the dual-core Xtensa LX6 CPU architecture, the server runs on **Core 0** while critical sweeps, hardware communication, and closed-loop control are pinned to **Core 1**, preventing HTTP overhead from causing timing jitters in measurements.

### 1.2 Digital-to-Analog Converters (DAC): Dual MCP4725
To capture the subthreshold region where current varies exponentially with gate voltage, high DAC resolution is critical. The internal 8-bit DAC of the ESP32 yields only $12.9\text{ mV/step}$ (inadequate for subthreshold modeling). 
The platform utilizes two external **MCP4725** 12-bit DACs communicating via I2C:
* **Address 0x60** (ADDR pin connected to GND): Controls the Gate Voltage ($V_{GS}$).
* **Address 0x61** (ADDR pin connected to VCC): Controls the Drain Voltage ($V_{DS}$) via a buffer.

$$Res = \frac{V_{ref}}{4096} = \frac{5.0\text{ V}}{4096} \approx 1.22\text{ mV/step}$$

Writing to the DAC is executed in I2C Fast Mode (400 kHz) targeting the output register directly (skipping the EEPROM write cycle), reducing latency from $5\text{ ms}$ to under $0.5\text{ ms}$ per write.

### 1.3 Analog-to-Digital Converter (ADC): ADS1115
To bypass the high noise floor ($\approx 2\text{--}5\text{ mV}$) and severe non-linearity of the ESP32's internal ADC, the 16-bit **ADS1115** delta-sigma converter is used. 
It features a programmable gain amplifier (PGA) dynamically configured by firmware to optimize resolution:
* **$\pm0.256\text{ V}$ Full Scale Range (FSR)**: Yields $7.81\ \mu\text{V/bit}$ resolution for low-current shunt measurements on channel A3.
* **$\pm6.144\text{ V}$ Full Scale Range (FSR)**: Yields $187.5\ \mu\text{V/bit}$ resolution for high-voltage and high-current readings on A0, A1, and A2.

### 1.4 Precision Operational Amplifier: LT1013
The LT1013 (dual precision op-amp) is utilized in two critical stages:
1. **Drain Voltage Buffer**: Operates as a unity-gain buffer/power stage to supply up to $100\text{ mA}$ to the Drain terminal of the DUT without causing voltage drops at the DAC output.
2. **Shunt Voltage Amplifier**: Amplifies the tiny voltage drop across the shunt resistor by a calibrated gain of **$31.3039\times$** (fed into channel A3 of the ADS1115) to detect currents in the nanoampere range.

## 2. Power Supply & Voltage Domains

To minimize analog noise and reference drifts, voltage domains are partitioned as follows:

| Subsystem / Node | Operating Voltage | Power Source | Notes |
| :--- | :--- | :--- | :--- |
| ESP32 DevKit | $3.3\text{ V}$ | Onboard 3.3V LDO regulator | Powered via USB ($5\text{ V}$) |
| MCP4725 (VGS & VDS) | $5.0\text{ V}$ | Direct USB Rail | Serves as the DAC voltage reference ($V_{ref}$) |
| ADS1115 ADC | $5.0\text{ V}$ | Direct USB Rail | Powered at 5V for matching signal ranges |
| LT1013 Op-Amp | $5.0\text{ V}$ | Direct USB Rail | Powered at 5V; rail-to-rail swing limits at ~3.5V |
| DUT Gate Terminal | $0 \to 5.0\text{ V}$ | Gate DAC (MCP4725) | High impedance gate input |
| DUT Drain Terminal | $0 \to 5.0\text{ V}$ | Drain DAC + LT1013 Buffer | Low impedance source/sink |

## 3. Passive and Active Shunt System

Depending on the operation mode, the user selects between two Shunt Resistors ($R_{shunt}$) using a physical toggle or switch.

* **$100\ \Omega$ Shunt (Subthreshold Mode)**: Used to maximize the voltage drop generated by nano-to-microampere currents. The voltage is amplified $31.3039\times$ by the LT1013, mapping a $100\ \text{nA}$ current to a readable $313\ \mu\text{V}$ signal.
* **$1\ \Omega$ Shunt (Saturation and Output Curve Modes)**: Used for higher currents (up to $500\text{ mA}$) to minimize source degeneration. At $100\text{ mA}$, the voltage drop is $100\text{ mV}$.

### 3.1 Overcurrent Protection Threshold
To prevent thermal damage to the DUT or shunt resistors, the firmware implements a hard safety ceiling. If the calculated drain current ($I_{ds}$) exceeds **$500\text{ mA}$**, the firmware immediately:
1. Shuts down both DACs ($V_{GS} = 0\text{ V}$, $V_{DS} = 0\text{ V}$).
2. Saturates the active bleeder to discharge any capacitance.
3. Aborts the sweep and sends a hardware error packet to the Web UI.

## 4. Auxiliary Hardware Circuits

### 4.1 Active Bleeder (2N3904 NPN + GPIO14)
When a sweep finishes, capacitive nodes on the PCB and breadboard retain charge, causing residual voltage at the Drain terminal. This causes incorrect readings at the beginning of the next sweep.
An active bleeder circuit is added:
* During **Standby** and **Idle** states, **GPIO14** is set to `HIGH`, saturating a 2N3904 NPN transistor which pulls the Drain node directly to GND.
* During **Active Measurement** states, **GPIO14** is pulled `LOW`, shutting off the transistor to isolate the node and allow precise voltage control by the Drain DAC.

### 4.2 Hardware Debug Logging Control (GPIO12)
No firmware recompilation is needed to enable full serial debugging. The state of **GPIO12** is read during initialization:
* **GPIO12 jumpered to GND**: Activates all log levels (`DEBUG`, `INFO`, `WARNING`, `ERROR`).
* **GPIO12 floating**: Limits logs to `INFO` and `ERROR` to minimize serial overhead and save CPU cycles.
